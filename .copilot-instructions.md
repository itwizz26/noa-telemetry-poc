# NOA Telemetry Engine Development Rules

## System Architecture Context
- Backend: Python 3.11+, Django, Django REST Framework, Celery, Redis.
- Frontend: Next.js 14+ (App Router), TypeScript, TailwindCSS.
- Infrastructure: Docker Compose, LocalStack (simulating AWS SQS, Secrets Manager), Terraform.
- Database: PostgreSQL (with a focus on high-frequency time-series optimization).

## Core Engineering Principles
1. **Absolute Idempotency:** Every incoming meter telemetry payload must be uniquely identifiable. Under no circumstances should duplicate events result in double-billing or duplicate records. Use PostgreSQL unique constraints.
2. **Strict Decoupling:** The web ingestion endpoints must never do direct processing or database blocking writes. They must drop payloads instantly into an SQS queue.
3. **No Placeholders:** Write production-ready, clean, maintainable Python and TypeScript code. Bypassing Django ORM via `bulk_create` with upsert conflicts is preferred for telemetry loops.

## Git Branching Strategy
- `main` is the production branch and must remain stable.
- `dev` is the active development branch for this repo.
- Create feature branches from `dev`.
- Merge completed feature branches back into `dev` first.
- Once `dev` is validated, merge `dev` into `main` for production.
- Keep `main` protected from direct feature work unless it is a hotfix.
